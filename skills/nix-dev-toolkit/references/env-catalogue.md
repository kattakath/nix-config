# Generating env tooling from one catalogue

The point of the catalogue is that `env-doctor`, `env-template` and the dev-shell banner are
**generated** from a single attrset. A hand-maintained `.env.example` drifts from the code within
weeks; a generated one cannot.

## The attrset

```nix
envCatalogue = {
  # need   : required | optional | ci | local
  # secret : true → tooling reports PRESENCE ONLY, never the value
  # used   : true when application source reads it; omit for tooling-only vars
  # note   : why it exists, or the one thing that is easy to get wrong
  DATABASE_URL = {
    need = "required"; secret = true; used = true;
    note = "Runtime URL. Must carry ?schema=... on providers that namespace enums.";
  };
  VERCEL_TOKEN = {
    need = "required"; secret = true;
    note = "The CLI reads this from the environment; never pass --token.";
  };
  CLOUDFLARE_API_TOKEN = { need = "optional"; secret = true; note = "wrangler / DNS."; };
  PG_PORT = { need = "local"; secret = false; };
};
```

Keep `used` honest. Platform tokens (`CLOUDFLARE_API_TOKEN`, `VERCEL_TOKEN`, `GH_TOKEN`) are
consumed by *tooling*, not read by the app — mislabelling them sends someone hunting for a
`process.env` reference that does not exist.

## Seeding it from the source

Do not invent names. Harvest, then annotate:

```bash
grep -rhoE 'process\.env\.[A-Z0-9_]+' src/ | sed 's/process\.env\.//' | sort -u        # app reads
grep -rhoE '\$\{\{ *secrets\.[A-Z0-9_]+' .github/workflows/ | grep -oE '[A-Z0-9_]+$' | sort -u
grep -rhoE '\$\{\{ *vars\.[A-Z0-9_]+' .github/workflows/ | grep -oE '[A-Z0-9_]+$' | sort -u
```

Anything in the harvest but not in the catalogue is a gap; anything in the catalogue but not the
harvest is either tooling-only (fine, mark `used` absent) or dead (delete it).

## Rendering: use a TSV side-file

Interpolating a Nix attrset into a shell script invites quoting bugs — notes contain spaces, quotes,
and `?`. Flatten to a tab-separated file at build time and let the shell read it:

```nix
lib = nixpkgs.lib;
envNames = lib.attrNames envCatalogue;
isSecret = n: envCatalogue.${n}.secret or false;

envTsv = lib.concatMapStringsSep "\n" (n:
  let e = envCatalogue.${n}; in
  lib.concatStringsSep "\t" [
    n
    (e.need or "optional")
    (if isSecret n then "secret" else "plain")
    (e.note or "")
  ]) envNames;

envTsvFile = pkgs.writeText "env-catalogue.tsv" envTsv;
```

Tabs are safe here because no field may contain one — keep notes single-line.

## `env-doctor`

Reports presence only. This is the rule that matters most: a diagnostic that prints a token is
worse than no diagnostic.

```bash
miss=0; total=0
printf '%-34s %-9s %-8s %s\n' VARIABLE NEED KIND STATUS
while IFS=$'\t' read -r n need kind _note; do
  [ -z "$n" ] && continue
  total=$((total+1))
  # Indirect expansion tests PRESENCE without ever expanding into output.
  if [ -n "${!n:-}" ]; then st="set"; else
    st="MISSING"; [ "$need" = required ] && miss=$((miss+1))
  fi
  printf '%-34s %-9s %-8s %s\n' "$n" "$need" "$kind" "$st"
done < "$CATALOGUE"

echo
if [ "$miss" -gt 0 ]; then echo "$miss required variable(s) missing."; exit 1; fi
echo "all $total variables present."
```

Rules the implementation must keep:

- Print `$n` (the **name**), never `${!n}` (the value).
- `[ -n "${!n:-}" ]` — the `:-` matters under `set -u`, which `writeShellApplication` enables.
- Exit non-zero only for missing **required** vars, so it is usable as a CI gate.
- Add a `--only <need>` filter if the list grows past ~50 entries.

Note that `nix run .#env-doctor` sees only the ambient environment — it does not load `.env` files.
Say so in the command's own help text, or a user will read a wall of `MISSING` as a broken setup.

## `env-template`

Writes a `.env.example` with **blank** values, notes as comments, and refuses to clobber:

```bash
out="${1:-.env.example}"
[ -e "$out" ] && { echo "refusing to overwrite $out" >&2; exit 1; }
{
  echo "# Generated by \`nix run .#env-template\`. Values are intentionally BLANK."
  echo "# Never commit a real secret."
  echo
  while IFS=$'\t' read -r n need kind note; do
    [ -z "$n" ] && continue
    [ -n "$note" ] && echo "# $note"
    echo "# need=$need kind=$kind"
    echo "$n="
    echo
  done < "$CATALOGUE"
} > "$out"
echo "wrote $out"
```

Refusing to overwrite is deliberate: the file people actually edit is `.env`, and a template
regeneration must never be able to destroy a populated one by a one-character typo.

## Dev-shell banner

Show counts, not contents — enough to tell whether the shell is usable, without a wall of text:

```nix
shellHook = ''
  echo "dev shell — $(node --version), psql $(psql --version | awk '{print $3}')"
  echo "env: run 'nix run .#env-doctor' (${toString (builtins.length envNames)} catalogued vars)"
'';
```
