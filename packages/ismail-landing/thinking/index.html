How I think.

Engineering tenets

Five rules I actually build by — not slogans. Each one is a habit that showed up the same way across fifteen years of production systems, and each links to the work that proves it.

The tenets

01 — 05

  1. 01

    Tenet 01

    Incidents become invariants.

    Every postmortem ends as a CI-enforced guard, not a wiki page — idempotency is a platform-wide contract across the whole Lambda fleet, with advisory-locked migrations that cannot race. The same failure can't recur quietly, because the fix is the check that now blocks the pipeline.

    Proof — how I work

  2. 02

    Tenet 02

    Security is the shape, not a patch.

    Tenant boundaries are drawn so cross-tenant escalation is structurally impossible — JWT audience isolation and least-privilege IAM decide it at construction time, not a rule bolted on after. Fail-closed gates and no stored keys in CI come from the same instinct.

    Proof — the Takeoff platform

  3. 03

    Tenet 03

    Reuse before rebuild.

    I build to learn a domain, then delete what a maintained tool already does — one bespoke ~40-file engine came out for a single dependency. The deliverable is less surface area for your team to carry, not more code.

    Proof — how I work

  4. 04

    Tenet 04

    Own the whole path, cloud included.

    I ship end to end — the backend and the AWS beneath it, the release pipeline, the migration; a national platform moved DigitalOcean → AWS with zero downtime under one owner. Deployment stops being the risky part of the week when the same person owns it from code to cloud.

    Proof — selected work

  5. 05

    Tenet 05

    Claim only what I can prove.

    Every number on this site is graded — proven outcome or self-measured — and I never blur the two. If I can't walk you through the measurement and where it stops being provable, it doesn't get stated.

    Proof — the evidence ledger

Why write these down

These are testable, not aspirational.

If a tenet doesn't survive contact with a real system, it isn't one. Bring me the hardest problem in your stack and press on any of them.
