# ADR-016 — One repo shape for the whole fleet

**Status:** **DECIDED 2026-11-26** (each point chosen click-to-select by the operator). Execution
is tracked in the "Fleet Shape Program" Google Tasks list; this file records the decisions.

**Question.** The two owners (org `kattakath`, user `ismailkattakath`) hold 19 working repos.
They share a CI gate but little else: flakes are hand-copied, licences and community files are
missing, READMEs are stale. What one shape should every repo have, how is it delivered and kept,
and which community standards measure it?

## 1. Verdict

- **Share logic, generate files, measure against community graders.** Flake logic comes from one
  kit consumed as an input, never copied. Per-repo files are generated from that kit and checked
  for drift. Conformance is graded by tools the community already runs, not by our taste.
- **Three homes, by what GitHub allows:** an owner-level `.github` repo for files GitHub can
  default; the kit for files that must live in each repo; terranix for repository settings.
- **README, docs and the About section are owned by one team**, written to standard-readme with
  verified badges, and kept honest by ADR-014's generated spans.

## 2. Evidence (measured 2026-11-26)

- **Census** of 43 repos (15 archived): 19 own working repos. 8 hand-copy one flake pattern
  (`forAll`, treefmt-nix, one devPackages list, `formatting` + `toolchain-complete` checks),
  now locked to 4+ different nixpkgs revisions. 6 public repos have no LICENSE. 10 of 17 have no
  topics; none has a social preview. Shared-workflow pins lag by 4 to 6 commits.
- **Community profile API:** nix-config 75, listing-lens 100, website 42, kattakath.github.io 37.
  The API cannot see issue forms, so it is not gated on that field.
- **OpenSSF Scorecard v5.7.0** (run locally): nix-config 5.8, listing-lens 6.2. Fixable:
  Token-Permissions, SAST, one unpinned action. Structural, accepted: Code-Review and
  Branch-Protection, because the operator pushes to `main` by policy.
- **GitHub docs:** default community files come from a PUBLIC `.github` repo per owner,
  personal accounts included; "You cannot create a default license file".

## 3. The shape

| Layer | What | Home |
|---|---|---|
| Defaultable community files | CODE_OF_CONDUCT (Contributor Covenant 3.0), CONTRIBUTING, SECURITY, SUPPORT, issue forms, PR template | `kattakath/.github` and a new public `ismailkattakath/.github` |
| Per-repo files | LICENSE (MIT for code, CC-BY-4.0 for sites), `.envrc` (`use flake` + `dotenv_if_exists .env`), `.devcontainer/devcontainer.json` (ADR-015, `:1`), `.editorconfig`, `.gitattributes`, REUSE metadata | generated by `repo-kit`, drift-checked |
| Flake logic | devShell from one package list, treefmt, `formatting` and `toolchain-complete` checks, one shared nixpkgs input | `repo-kit` flakeModule |
| Repo settings | description, homepage, topics, `has_*`, merge methods, visibility, default branch | terranix `github_repository` |
| Conformance | the graders in § 6 | CI, plus a fleet-doctor census rule |

## 4. `repo-kit`

- **Owner: `ismailkattakath`** (the operator's call). A public flake input works for either
  owner's repos. The owner is chosen once: a moved repo still fetches through GitHub's redirect,
  but a consumer's lock keeps the old owner (measured on `github:LnL7/nix-darwin`).
- **Composition: adopt, then glue.**
  - flake-parts (the module system nix-config already uses).
  - treefmt-nix and git-hooks.nix flakeModules.
  - **mightyiam/files** for generated files: a `write-files` app plus one flake check per file
    that diffs the repo against the Nix source. A pinned input, bumped by PR.
  - Ours: the `repoKit` options (one package list, licence and identity knobs), the file texts,
    one nixpkgs input every consumer `follows`.
- **Rejected:**

| Option | Why it lost |
|---|---|
| nixago | Stale (last release 2022); symlinks on shell entry, no drift check |
| devenv | Its own CLI, state and lock; files applied on shell entry, never checked |
| divnix/std | Stale and heavy |
| blueprint, flakelight | A second flake framework beside flake-parts |
| numtide/devshell | Self-declared unstable; `mkShell` is enough |
| Flake templates, GitHub template repos | Copy once and never sync: the drift this ADR removes |
| copier | Mature, but it copies flake logic instead of sharing it, and adds a Python toolchain |
| Export from nix-config | Every consumer would inherit nix-config's large input set |

- **Weakest assumption:** mightyiam/files has one maintainer (92% of commits). It is about 200
  lines in one module. **Reopen** (vendor it) if upstream stalls or breaks its option names again.

## 5. Repository settings as code

- **`github_repository` with `lifecycle { destroy = false }`** (OpenTofu 1.12+): a destroy, a
  replace or a dropped block becomes a forget, so the repo is never deleted. Topics go on the
  same resource (the provider's `github_repository_topics` is "only meant to be used if the
  repository itself is not handled via terraform"); `github_branch_default` beside it.
- **Import-only first apply**, every attribute pinned at its live value (an unset attribute is
  sent as false or the provider default). The re-plan must read **No changes**.
- **Out:** Pages and the vulnerability-alert resources (their delete turns the feature off),
  archived repos, forks, and every private repo (no private name enters this public repo).
- **Rejected:** `archive_on_destroy` (never read back, so every imported repo plans an update and
  import-only fails); a wide `ignore_changes` (declares nothing).

## 6. Graders

| Grader | Measures | Wiring |
|---|---|---|
| OpenSSF Scorecard | supply-chain practices; publishes the public score and badge | `scorecard-action` with `publish_results` |
| REUSE | every file's licence; required where MIT code and CC-BY content mix | `reuse-action`, `LICENSES/`, `REUSE.toml` |
| Community profile | GitHub's checklist, plus a direct `ISSUE_TEMPLATE` check | fleet-doctor census rule |
| Ecosystem | repo-review (Python), flake-checker (Nix), zizmor and actionlint (workflows) | per kind, via the shared gate |

## 7. README, docs and About

- **README:** standard-readme section order; badges on rows under the title, each with real alt
  text, and **only badges verified to render a value** (an HTTP 200 is not proof: the Scorecard
  and REUSE badges render errors until set up).
- **Docs:** plain `docs/` in the Diátaxis layout (tutorials, how-to, reference, explanation),
  facts in ADR-014 generated spans, links checked by lychee. Rejected: MkDocs Material (end of
  life 2027-05-05), Docusaurus (heavy), Starlight (pre-1.0), mdBook (ADR-014 § 7).
- **About:** description (under 120 characters, matching the README), homepage and up to 20
  topics, all declared in § 5; a 1280×640 social preview per repo, uploaded by hand (no API).

## 9. Reopen when

- mightyiam/files stalls or churns (vendor it, § 4).
- A grader's structural ceiling starts blocking a real goal (e.g. a badge requirement).
- A second org joins the fleet (the `.github`-per-owner model scales by one repo per owner).
